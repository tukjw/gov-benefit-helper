# 부하 테스트 기준 측정 (#96)

> 측정 전이다. [부하 테스트 절차](../ops/load-test.md)로 측정한 뒤 아래 항목을 채운다.

운영 API의 기준 지연·처리량·오류율과 한계 지점을 [측정 기록 형식](../product/development.md#측정-기록-형식)에 맞춰 남긴다. 측정 방식은 [결정 0037](../decisions/0037-proxmox-deploy-metrics-and-load-test.md), 재현 스크립트는 `scripts/loadtest/`, 원본 결과는 `docs/research/load-test-baseline/results/`에 있다. 병목의 개선과 성능 목표 결정은 다루지 않는다.

## 2. 데이터와 실행 환경

- 데이터: 혜택 건수(실데이터, 출처 공공서비스 API), 테스트 계정 1,000개(합성)
- 앱 이미지 태그와 실행 구성 커밋:
- VM 사양: app, db, 부하 생성
- 설정: 커넥션 풀, Tomcat 스레드, JVM 힙

## 3. 요청 분포와 실행 방식

- 단계마다 3분, 첫 단계 앞 워밍업 3분(기준값에서 뺀다). 거친 단계 → 세밀 단계(25% 간격)
- 가상 사용자별 `CF-Connecting-IP`, 응답 본문은 버린다(`discardResponseBodies`)
- 측정 중 API 차단(`cloudflared` 중지). 부하 도구의 요청만 앱에 닿았다.

## 4. 시나리오별 결과

시나리오마다 단계별로 목표 속도, 처리량, p50·p95·p99(실패 포함), 오류율, 못 보낸 요청, app·db CPU, 커넥션 풀 대기, MySQL 초당 쿼리, 부하 생성 VM CPU를 적는다. 한계가 보이기 시작하는 요청 속도와, 어느 자원이 먼저 찼는지 근거를 함께 적는다.
