# 구현 플랜

이슈 하나당 플랜 파일 하나를 둡니다. 파일명은 이슈 브랜치와 같은 `<이슈번호>-<슬러그>.md`입니다.

## 헤더

첫 줄의 `status` 아래에 제목과 브랜치를 적습니다. 이슈는 제목의 `#<이슈번호>`로 가리키고 URL은 적지 않습니다. 브랜치 줄에는 분기 원점과 그 시점의 커밋을 함께 남깁니다.

```
status: draft

# 구현 계획 — #<이슈번호> <이슈 제목>

브랜치: `<브랜치 이름>` (develop `<sha>` 기준)
```

hotfix 플랜만 `main` 기준으로 적습니다.

## 상태

파일 첫 줄에 `status: draft | in-progress | done`을 둡니다.

- `draft`: 작성됨. 아직 착수하지 않음.
- `in-progress`: 브랜치에서 작업 중.
- `done`: PR을 올림. PR 직전 마지막 커밋에서 바꾸며, 머지 후에도 기록으로 남깁니다.

## 작성 시점

선행 이슈가 머지된 뒤에 작성합니다. 선행 결과에 따라 시그니처나 파일 위치가 바뀌므로 미리 써 두면 낡습니다.

## 필수 항목

- 목표 및 범위 (포함, 제외)
- 확인된 사실과 제약
- 설계 결정 (대안이 있을 때만)
- 단계별 구현 계획 (파일과 함수 이름 명시)
- 완료 조건 매핑 (이슈의 완료 조건을 그대로 복사)
- 검증 명령
- 결정 필요 (없으면 "없음")
