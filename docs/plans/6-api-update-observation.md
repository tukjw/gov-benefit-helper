## 설계 결정

1. **재등장 집계는 새 하위 명령 `series`로 한다.** `analyze --compare`를 여러 번 돌린 결과를 사람이 이어 붙이면 다시 실행할 수 없다(완료 조건 6). `series --snapshots <id> <id> ...`는 다음 순서로 동작한다.
   - 각 스냅샷의 목록을 기존 `load_snapshot()`으로 올린다.
   - 모두 합쳐 `obs(순번, 스냅샷, 서비스ID, 서비스명, 수정일시)` 표를 만든다.
   - `snapshot_series.sql`을 실행한다.

   목록만 쓰는 이유는 세 경로의 서비스ID 집합이 매 스냅샷 같았기 때문이다(`id_consistency.sql`). 상세·지원조건까지 올리면 메모리만 더 쓴다.
2. **일별 결과 파일은 지금 생성기 그대로 커밋한다.** 각 파일은 직전 스냅샷과 비교한 결과다. 10/1 파일은 9/29와 비교했다(9/30 없음). 보고서 표에는 이 파일들의 수치를 옮긴다.

3. `scripts/research/gov24/gov24.py`에 `series` 하위 명령을 더한다.
   - `cmd_series(args)`: 스냅샷마다 `load_snapshot(con, snapshot_path(id), f"s{i}")`를 실행한다. 이어서 `obs` 표를 `UNION ALL`로 만든다.
   - `write_series_results(args, sections)`: `results/series-<첫 스냅샷>-<마지막 스냅샷>.md`에 쓴다. 머리말 형식은 `write_results()`와 같다.
   - 인자 `--snapshots`는 2개 이상이고, 준 순서를 시간 순서로 본다. 스냅샷 ID 순서와 다르면 멈춘다.
4. `scripts/research/gov24/queries/snapshot_series.sql`을 작성한다. 정렬 순서는 고정한다.
   - 스냅샷별 목록 건수.
   - 사라짐 사건: 앞 시점에는 있고 다음 시점에는 없는 서비스ID. 서비스ID·시점·직전 수정일시를 남긴다.
   - 재등장 사건: 사라졌다가 이후 시점에 다시 나타난 서비스ID. 몇 회 연속으로 없었는지, 다시 나타날 때 수정일시와 서비스명이 바뀌었는지를 남긴다.
   - 마지막 시점까지 계속 없는 서비스ID와 연속으로 없었던 횟수.
   - 첫 시점에 없다가 나타난 서비스ID의 등록일시 분포. 신규 등록인지, 오래된 서비스의 재노출인지 나눈다.
5. `series`를 9/28~10/8 스냅샷 전체로 실행한다. 결과가 수작업으로 찾은 사례(확인된 사실의 5건)와 맞는지 확인한다.
6. 보고서 `docs/research/gov24-api-data.md`를 고친다.
   - 머리 표: 확인 날짜, 표본, 호출 수, 집계 결과 행에 #6 기간과 결과 파일 링크를 더한다.
   - §8:
     - 시점별 추가·사라짐·내용 변경·수정일시만 변경·조회수만 변경 건수 표와 예시. 수집하지 못한 9/30·10/7을 적는다.
     - 수정일시 변화와 내용 변화가 어긋난 건수.
     - 수정일시 필터 조회와 목록 비교의 차이.
     - 재등장 건수와 예시(`series` 결과).
     - 반영 시점 관찰. 같은 날 수정은 다음 날 반영되고, 00:30 자동 수정은 재노출과 함께 나타난다.
     - 정기 수집 시각에 주는 함의.
   - §9 `DEC-DATA`: "비노출·종료 판단은 #6에서…" 문장을 선택지 표로 바꾼다. 선택지는 다음과 같다.
     - 사라진 즉시 비노출.
     - N회 연속 부재 후 비노출.
     - 비노출만 하고 종료는 원문 근거(신청기한 등)가 있을 때만.
     - 표시 유지에 상태 배지만.

     근거는 재등장 사례의 부재 기간과 사라짐 건수에서 가져온다.
   - §10: 관찰 기간, 휴일이 몰린 기간(추석·개천절·대체공휴일), 반영 시각을 구간으로만 안다는 한계를 적는다.
7. `docs/product/data-source.md`의 "남은 미확인" 둘째 항목을 확인한 사실로 바꾼다. 갱신 주기, 수정일시와 내용 변경의 관계, 사라진 항목의 의미가 대상이다. 남는 미확인(정확한 반영 시각, 장기 부재의 의미)만 남긴다.

set -a; . ~/.config/gov-benefit-helper/gov24.env; set +a

  git grep --untracked -nF -e "$k"
  git log -p origin/develop..HEAD | grep -nF -e "$k"
done

# 2. 참조된 요구사항·결정 ID가 모두 정의돼 있는지
comm -23 <(grep -rhoE 'REQ-[A-Z]+-[0-9]+' docs | sort -u) \
  <(grep -hoE '^### REQ-[A-Z]+-[0-9]+' docs/product/requirements.md | cut -c5- | sort -u)

  <(grep -hoE '^\| DEC-[A-Z]+' docs/product/development.md | cut -c3- | sort -u)
