# 0031. 비회원 프로필 값의 브라우저 보관

- 상태: 채택
- 날짜: 2026-10-27
- 출처: #74, [플랜](../plans/74-personal-pages.md)

## 배경

비회원도 프로필 값을 입력해 조건 비교를 볼 수 있다(`REQ-PROFILE-01`, `REQ-MATCH-01`). 서버는 비회원의 값을 저장하지 않고 조건 비교 요청 본문으로만 받는다(#67). 그래서 입력한 값을 목록·상세·새로고침 사이에 이어 쓰려면 브라우저 어딘가에 둬야 했다. 값에는 생년월일과 거주지가 들어 있고, 이 서비스에서 개인정보를 브라우저 저장소에 두는 곳은 이것뿐이다.

## 결정

비회원이 입력한 프로필 값은 `sessionStorage`의 `gbh:guest-profile` 키에 프로필 저장 요청(`ProfileRequest`)과 같은 모양의 JSON으로 둔다. 서버에는 조건 비교 요청 본문으로만 보낸다. 로그인에 성공하면 지우고, 로그인 사용자는 저장된 프로필만 쓴다.

- 같은 탭에서는 새로고침·이동해도 남고, 탭을 닫으면 지워진다. 비회원 화면(프로필 입력, 조건 비교 목록)에 "입력한 정보는 서버에 저장되지 않아요."를 한 줄로 보여준다. 값이 탭에 남으므로 "서버에"를 빼고 "저장되지 않아요"라고만 쓰지 않는다. 탭을 닫으면 지워진다는 안내는 문구가 길어져 두지 않았다(2026-10-27 사용자 결정).
- 저장소 접근이 막혔거나(사생활 보호 모드 등), JSON이 깨졌거나, 모양이 맞지 않으면 입력하지 않은 것으로 본다.
- 값의 검증은 서버가 한다. 저장하기 전에 조건 비교 API로 보내 400이면 항목별 오류를 보여주고 저장하지 않는다. 저장해 둔 값이 나중에 400이 되면 입력 화면으로 보내 다시 제출하게 한다.
- 액세스 토큰은 이 결정과 관계없이 저장소에 쓰지 않는다([결정 0030](0030-frontend-auth-session.md)).

## 근거

- 모듈 메모리에만 두면 새로고침할 때 사라져, 상세에서 새로고침한 비회원이 다시 입력해야 한다.
- `localStorage`는 탭을 닫아도 남아 공용 컴퓨터에 생년월일이 남는다. `sessionStorage`는 탭이 닫히면 브라우저가 지운다(2026-10-27 사용자 결정).
- 요청 본문과 같은 모양으로 두면 읽은 값을 그대로 조건 비교 API에 보낼 수 있고, 프론트에 검증 규칙을 따로 두지 않아도 된다(`REQ-PROFILE-01`: 비회원 값의 검증 기준은 프로필 저장과 같다).
- 로그인하면 지우는 이유는 저장된 프로필과 탭의 값이 함께 있으면 어느 값으로 비교했는지 헷갈리기 때문이다. 비회원 값을 프로필로 옮기는 기능은 두지 않았다(#74 범위 밖).
- 한계: 같은 탭에서 스크립트가 실행되면(XSS) 이 값을 읽을 수 있다. 오래 쓸 수 있는 인증 정보가 아니고 탭을 닫으면 지워지므로 받아들였다.

## 적용 위치

- `frontend/src/lib/profile/guestProfile.ts`: `readGuestProfile`, `writeGuestProfile`, `clearGuestProfile`, `GUEST_NOTICE`
- `frontend/src/pages/profile/profileRoute.ts`: 비회원 입력의 검사와 저장
- `frontend/src/pages/match/matchRoute.ts`, `frontend/src/pages/benefits/detail/benefitDetailLoader.ts`: 비회원 조건 비교
- `frontend/src/pages/account/login/loginRoute.ts`, `frontend/src/pages/account/signup/signupRoute.ts`: 로그인 뒤 지우기

## 영향

- 비회원의 프로필 값을 쓰는 새 화면은 `guestProfile.ts`로만 읽고 쓴다. 다른 저장소에 개인정보를 두지 않는다.
- 비회원 값을 로그인 뒤 프로필로 옮기거나 탭 사이에 공유해야 하는 요구가 생기면 이 결정을 다시 검토한다.
