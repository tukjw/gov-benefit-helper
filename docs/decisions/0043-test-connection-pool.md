# 0043. 테스트 커넥션 풀 크기

- 상태: 채택
- 날짜: 2026-11-03
- 출처: #113, [플랜](../plans/113-test-db-connection-limit.md)

## 배경

테스트는 MySQL 컨테이너 하나를 함께 쓰고([결정 0033](0033-test-shared-mysql.md)), Spring 테스트 컨텍스트마다 커넥션 풀이 하나씩 생긴다. HikariCP 기본값에서는 최소 유휴 연결 수가 최대 크기(10)와 같다. 그래서 풀은 시작하자마자 연결을 10개 채우고, 유휴 연결을 닫지 않는다. Spring은 실행이 끝난 컨텍스트를 캐시에 남기므로, 테스트는 한 번에 하나씩 도는데도 동시 연결 수는 컨텍스트 수 × 10으로 늘어난다.

develop `29a34a1`에서 `./gradlew test`는 컨텍스트 18개를 띄우고, 앱 계정의 연결 한도 151을 다 썼다. #107 작업 중 테스트 클래스를 하나 더 만들어 컨텍스트가 하나 늘자, `PublicMatchApiTest`가 `Too many connections`로 컨텍스트를 띄우지 못해 테스트 9개가 실패했다. #113에서 같은 실패를 재현했다.

## 결정

테스트 커넥션 풀은 최소 유휴 연결 1개, 유휴 연결 정리 10초로 둔다. 최대 크기(기본 10)는 줄이지 않는다. 풀 설정은 테스트 공통 설정 한 곳에만 두고, 테스트 클래스에서 덮지 않는다.

## 근거

- 측정: 로컬에서 `./gradlew cleanTest test`를 돌리는 동안, 그 실행이 띄운 MySQL 컨테이너의 `Max_used_connections`를 1초마다 읽었다. 값에는 측정용 관리자 연결이 최대 1개 들어 있다. 바꾸기 전 값이 152인 것은 앱 계정이 151개를 다 쓰고, 한도에 닿았을 때 관리자에게만 허용되는 추가 연결 1개를 측정이 썼기 때문이다. 컨텍스트를 늘리는 데는 설정이 다른 임시 테스트 클래스를 썼다.

  | 상태 | 컨텍스트 | 최대 동시 연결 | 한도(151)까지 여유 | 결과 |
  | --- | --- | --- | --- | --- |
  | 바꾸기 전 | 18 | 152 | 0 | 통과 |
  | 바꾸기 전 + 임시 클래스 1개 | 19 (1개 시작 실패) | 152 | 0 | `PublicMatchApiTest` 9개 실패 |
  | 바꾼 뒤 | 18 | 28 | 123 | 통과 |
  | 바꾼 뒤 + 임시 클래스 1개 | 19 | 27 | 124 | 통과 |
  | 바꾼 뒤 + 임시 클래스 20개 | 38 | 44 | 107 | 통과 |

  전체 테스트 시간은 바꾸기 전 58초, 바꾼 뒤 54초로 늘지 않았다.
- 바꾼 뒤에는 캐시에 남은 컨텍스트가 연결을 1\~2개만 남기고, 나머지는 쉬기 시작하고 10\~40초 안에 닫는다(유휴 정리 10초 + HikariCP 정리 주기 30초). 연결을 쓰는 컨텍스트는 필요한 만큼 최대 크기까지 늘린다.
- 최대 크기를 줄이지 않는 이유: 동시성 테스트는 스레드 8개(`SignUp`·`RefreshToken`·`Bookmark`·`Profile` ConcurrencyTest)나 20개(`LoginAttemptConcurrencyTest`)로 연결을 동시에 쓴다. 풀이 작으면 요청이 풀에서 줄을 서서, 경합을 만들지 못한 채 통과할 수 있다.
- 유휴 정리를 10초(`10000`)로 두는 이유: HikariCP 7.0.2가 허용하는 최솟값이다. 0이 아니면서 10초보다 작으면 경고 후 기본값 10분으로 되돌린다(`HikariConfig.validateNumerics`).
- 최소 유휴를 0이 아니라 1로 두는 이유: 쉬던 컨텍스트로 돌아왔을 때 새 연결을 기다리지 않게 하나를 열어 둔다. 컨텍스트마다 1\~2개 차이라 한도에는 영향이 작다.
- 제외한 대안
  - 테스트 MySQL의 `--max-connections` 상향: 연결 수가 컨텍스트 수 × 10으로 늘어나는 구조가 그대로라 한계를 뒤로 미룰 뿐이다.
  - 최대 풀 크기 축소: 동시성 테스트가 확인하는 내용이 약해진다.
  - 컨텍스트 캐시 크기(`spring.test.context.cache.maxSize`) 축소: 캐시에서 밀려난 컨텍스트를 다시 띄우게 되어 테스트 시간이 늘어난다.

## 적용 위치

- `backend/src/test/resources/config/application.yaml`의 `spring.datasource.hikari`

## 영향

- 새 테스트 클래스가 컨텍스트를 하나 늘려도 따로 할 일이 없다. 쉬는 컨텍스트 하나가 연결을 1\~2개만 쥔다.
- 테스트 클래스의 `properties`나 `@DynamicPropertySource`로 `spring.datasource.hikari.*`를 덮지 않는다. 그 컨텍스트만 다시 연결을 쥐고, 설정이 달라져 컨텍스트도 하나 더 생긴다.
- 테스트 풀의 최대 크기를 줄이려면, 동시성 테스트가 여전히 경합을 만드는지 함께 검토하고 이 결정을 대체한다.
- 운영·로컬 실행의 커넥션 풀 설정과는 관계가 없다. 이 설정은 테스트 클래스패스에만 있다.
