# 정부 혜택 도우미 — 서비스 기획

작성일: 2026-09-27

이 문서는 지금까지의 대화와 현재 저장소를 바탕으로 만든 개발용 초안이다. 서비스 방향과 저장소에서 확인한 사실 외에, 출시 범위·세부 동작은 아래 제안안을 검토해 확정한다.

## 서비스 목적

사용자가 자신의 상황과 관련 있는 정부 혜택을 찾고, 신청 조건·방법·기한을 확인한 뒤 관심 혜택을 놓치지 않도록 돕는다. 현금뿐 아니라 교육·상담·바우처 등도 다룰 수 있으므로 서비스에서는 ‘혜택’ 또는 ‘지원제도’라는 말을 사용한다.

주요 사용자는 지원제도를 일일이 찾아보기 어렵고, 자신에게 관련 있는 제도인지 확인하고 싶은 개인이다. 특정 지역·연령·생활 상황으로 먼저 좁히지 않는다. 탐색은 전국의 모든 혜택, 개인화는 개인·가구 대상 혜택을 다룬다([DEC-SCOPE](development.md#결정한-사항)).

## 핵심 사용자 흐름

1. 키워드와 분야 등으로 혜택을 탐색한다.
2. 상세에서 지원 내용·조건·신청 방법·기한·공식 출처를 확인한다.
3. 간단한 내 정보를 입력하고, 확인 가능한 조건과 더 확인해야 할 조건을 구분해 본다.
4. 관심 있는 혜택을 저장하고 다시 찾아본다.
5. 이후 명확한 신청 기한에 대한 알림을 받아 공식 신청처로 이동한다.
6. 내 조건에 맞는 새 혜택이 수집되면 알림을 받는다.
7. 저장한 혜택의 기한·조건 등이 바뀌면 알림을 받는다.

## 단계별 범위 제안

| 단계 | 사용자에게 제공할 결과 | 포함 | 완료 판단 |
| --- | --- | --- | --- |
| 1차: 탐색 기반 | 실제 공공 데이터를 검색하고 신청처를 확인할 수 있음 | 수집·검색·상세·출처·갱신 정보 | 외부 API 장애 중에도 저장된 혜택 조회 가능 |
| 2차: 개인화 MVP | 내 상황으로 후보를 좁히고 관심 혜택을 관리할 수 있음 | 로그인·최소 프로필·검증 가능한 조건 비교·관심 저장. 조건 비교는 가입하지 않아도 프로필 값을 입력해 쓰고, 로그인은 프로필 저장·관심 저장처럼 기록을 남기는 기능에만 필요하다(2026-10-25, #67) | 사용자별 정보가 분리되고 판단 근거·한계가 보임 |
| 3차: 알림 | 저장한 혜택의 확인된 신청 기한과 변경 사항을 챙기고, 조건에 맞는 새 혜택을 알 수 있음 | 알림 동의·기한 알림 예약·변경·취소·새 혜택 감지·대상 선정·관심 혜택 변경 감지·실패 복구 | 재시도·서버 종료·기한 변경·재수집 시 중복 알림, 수집 실패를 변경으로 오인하는 상황을 검증 |

1차는 개발 중간 결과이며, 개인화를 포함한 2차까지를 최초 MVP로 제안한다. 알림은 MVP 이후 주요 기능으로 이어간다. 알림은 첫 공개 버전(2차 MVP)에 넣지 않는다([DEC-SCOPE](development.md#결정한-사항)). 기한 알림·새 혜택 알림·변경 알림 중 무엇을 먼저 만들지는 데이터 검증에서 확인한 기한·조건 품질을 보고 정한다.

자동 검증·배포·관측·백업은 기능 단계와 별개로, 배포할 기능이 생기는 시점에 맞춰 진행한다. 순서는 [개발 순서](development.md)의 운영 작업을 따른다.

## 초기 범위에 넣지 않는 제안

- 실제 수급 자격 확정, 소득·재산 자동 조회, 정부 사이트 대리 신청, 실제 심사 상태 조회.
- 모든 혜택의 자유서술 조건을 자동 판독하는 규칙 엔진이나 AI 판정.
- 중복 수혜 가능 여부, 미래 자격 시뮬레이션, 신청 준비 순서 자동 생성.
- 모든 조건을 빠짐없이 비교한다는 약속. 조건 비교는 `DEC-MATCH`에서 정한 항목만 한다.
- 혜택의 대상 지역·거주 요건 판정. 지역은 운영 기관 지역으로만 보여준다.
- 운영자용 웹 화면. 초기 수집 확인은 보호된 운영 수단으로 시작할 수 있다.

신청 준비 체크리스트·대안 혜택 안내는 이후 후보로 보관한다. 추천과 알림 자체를 독자적인 차별점이라고 주장하지 않는다.

## 기술 개선 원칙

기능은 사용자 문제를 해결하기 위해 만들고, 기술은 관찰한 문제에 맞춰 선택한다. 개선은 [측정 기록 형식](development.md#측정-기록-형식)에 맞춰 남긴다.

세부 기능의 완료 조건은 [요구사항](requirements.md), 기술 검증과 미정 사항은 [개발 순서](development.md)를 따른다.
